## 6c. Performance budget (PageSpeed mobile)
- Loading states: `FeedSkeleton` (`skeletons.tsx`) is hairline rows in the story list's shape with `animate-pulse`, never cards.
- Keep heavy client libraries off shared and home bundles. `AIMessage` must not import streamdown (`Response`): markdown blocks use `AIMarkdownMessage` (`ai-markdown.tsx`), which loads streamdown through `next/dynamic` in the client file `ai-markdown-body.tsx` (SSR on): imported directly it put ~140 KB gzip on every article page, deep analysis or not, because a Server Component's dynamic import is not code-split. Header, StoryList, menus and PWA sheets animate with the `@starting-style` utilities in `globals.css` (`panel-enter`, `menu-enter`, `fade-enter`, `sheet-enter`, `rise-enter`), not `motion` and not keyframes (`tailwindcss-animate` was removed). `Empty` is plain markup (Untitled's EmptyState pulled ~200 KB of illustrations; its file-icons loader ~470 KB).
- Check with Lighthouse before merging UI work: `npx lighthouse <url> --form-factor=mobile`. Also check every changed layout at 360 px for horizontal overflow, comparing `document.documentElement.scrollWidth` with the viewport you set (a mobile browser widens `innerWidth` to the content): a one-line card header with `shrink-0` badges made `/risk` and `/clusters/<id>` 644 px wide on phones (Nov 2026); `ArticleCard`'s header wraps, source + time kept together. A grid item's min-content still widens an `auto`/`1fr` track: `ArticleGrid` is `grid-cols-1` (minmax(0,1fr)), `FeedSkeleton` rows `minmax(0,1fr)`, and the article's people/organisation chips wrap (`whitespace-normal`; a 68-letter organisation name made an article 471 px wide). Text needs 4.5:1 contrast: topic labels use `utility-*-700`, the logo's teal is `#047c78` in light mode.
- Fonts: self-hosted `src/assets/fonts/inter-var.woff2` via `next/font/local` (`weight: "100 900"`, preloaded, 56 KB): Inter variable instanced to `opsz=14` and subset to Latin + Cyrillic + Ө Ү (U+04AE-04AF, U+04E8-04E9) + ₮ + the arrows/checks we print, with `tnum`. Two more files with the same subset (+ U+2248 ≈): `inter-display-var.woff2` (`--font-inter-display`, the `opsz=32` instance at `wght=650:850`, 40 KB) for headlines (`display: "optional"`: with `swap` a long article headline wraps to one more line in the fallback, so a late font shifted the page, CLS 0.147 → 0 with a 2.5 s font delay at Lighthouse's viewport) and `jetbrains-mono-500.woff2` (`--font-jb-mono`, from the JetBrains Mono release, 34 KB) for numbers and labels; both preloaded. Google's `next/font/google` Inter needed three files (175 KB) and did not preload the 83 KB cyrillic-ext one that holds Ө/Ү. Rebuild both files with `fonttools varLib.instancer InterVariable.ttf opsz=14` + `pyftsubset --unicodes=… --layout-features+=tnum,case,ccmp,locl --flavor=woff2` (and `Inter-Bold.ttf` → `--flavor=woff` for OG) when glyphs are missing; never add the `cyrillic-ext` Google subset back.
- `TimeAgo` prints the full date on the server and "7 цагийн өмнө" after hydration: never put it in a wrapping row whose line count can change with that swap. The article's source/time label takes its own line below `sm` (`basis-full`), because the longer server text wrapped under the source badge and the hydrated one did not (PageSpeed CLS 0.126 on every article, Oct 2026).
- Clock: `src/lib/now-store.ts` `useNow()` is the one shared 30 s clock (server snapshot 0) for every `TimeAgo` and the masthead ticker: no per-row effect, interval or setState. `StoryList` rows are `memo(StoryRow)` with handlers whose identity never changes (the read set is read through a ref), so a tap re-renders one row. `prefetch={false}` on the digest strip and TopicBar links (15 topic pages prefetched on every visit cost ~45 KB).
- After the Oct 2026 redesign (demo build, Lighthouse 12.x mobile, simulated throttling): `/` 90–95, article 95, digest 95, accessibility 100, CLS 0, TBT ≤ 70 ms; the built CSS went from 205 KB (32 KB gzip) to 162 KB (27 KB gzip) once `tailwindcss-animate` and the unused Untitled components were dropped. Home JS stays at ~218 KB gzip (the React + Next floor).
- Home JS (Oct 2026): ~216 KB gzip, of which ~185 KB is React + the Next runtime (the floor); our own code is ~30 KB (header ~13 KB, StoryList ~11 KB, PWA ~6 KB). Vercel Web Analytics loads as Vercel's plain script (`/_vercel/insights/script.js` + `window.va` stub in the layout, only when `VERCEL` is set), not the npm client, injected after `load` when idle (as a deferred script it was a 140 ms task inside mobile TBT); Speed Insights was removed (Lighthouse is our measure). `ShareButton` in StoryList is `next/dynamic` (loads on the first opened story).
- `/` and `/topic/<key>` render 20 stories (`FIRST_PAGE` in home-feed.tsx); "Цааш үзэх" in `StoryList` (`moreFeed`) fetches `/api/feed/<key>` (prerendered per `FEED_FILTERS`, `getFeed(key, 40)`) and appends the rest without repeating a shown story or cluster. 40 server-rendered rows were 1,000+ DOM nodes and 2 s of mobile TBT (Oct 2026 Lighthouse mobile 70).
- CSS diet 2 (Oct 2026, PageSpeed "render-blocking requests"): the `@tailwindcss/typography` plugin is gone; `src/styles/typography.css` (Untitled's `.prose`, plus the table rules the plugin used to add) styles every `.prose` block, so `prose-sm` / `prose-invert` no longer exist (dark mode comes from the tokens). Article screenshots were pixel-identical; the shared CSS went from 28.6 to ~25 KB gzip. `images.formats` puts AVIF first (the logo mark). Two PageSpeed items stay on purpose: "unused JavaScript" (~27 KB) is React DOM itself, and "legacy JavaScript" is Next's own built-in polyfill module (`next/dist/build/polyfills/polyfill-module`, ~1.5 KB real; Safari 16.4, inside Next's supported range, lacks `URL.canParse`), so neither is aliased away.
- `experimental.inlineCss` was measured and rejected: the 197 KB theme CSS was inlined three times (670 KB HTML).

## 6b. SEO
- `src/lib/site.ts` is the one source for `SITE_URL` (`NEXT_PUBLIC_SITE_URL` → `VERCEL_PROJECT_PRODUCTION_URL`), title, description and Mongolian keywords.
- `robots.ts` (disallows `/admin`), `sitemap.ts` (pages, topics `/topic/<key>`, every article), `news-sitemap.xml` (Google News, last 48 h), `feed.xml` (RSS).
- Every public page sets its own `alternates.canonical`. Never put a canonical or `openGraph.url` in the root layout: children inherit it and every page would point at `/`.
- JSON-LD: `NewsMediaOrganization` + `WebSite` in the layout, `NewsArticle` + `BreadcrumbList` on articles (`jsonLd()` escapes `<`). Page-level builders live in `src/lib/structured-data.ts` (`breadcrumbLd`, `datasetLd` naming the official creator and source, `personLd`): `/data` (two `Dataset`s: Mongolbank, opendata.mn), `/budget` (`Dataset`, ҮСХ), `/tax` (`WebApplication`), `/officials` (`ItemList` of members), `/officials/[id]` (`Person` with `alternateName` = short name + breadcrumb).
- Search intent (Oct 2026): the `<title>` and H1 carry the phrase people type, the catchy line moved to the kicker: /data "Валютын ханш, инфляц, эдийн засгийн тоо", /tax "Цалингийн татвар тооцоолуур", /budget "Монгол Улсын төсөв", /laws "Шинэ хууль, тогтоол"; an MP profile's title leads with the short name ("Д.Ганмаа (Даваасамбуу Ганмаа) — хөрөнгө, орлого, ирц") and links its constituency's places.
- OG images: `src/lib/og.tsx` (next/og). `ogImage` is the share card in the Ledger look: brand row, mono eyebrow with the topic square (`Topic.hex`), Inter Display headline, hairlines, the largest ₮ amount on the signal chip with its per-person share (`largestAmount`, `perPersonShare`); risk-flagged stories get the dark card. Fonts are WOFF subsets (Satori reads no WOFF2): `inter-700.woff` (Latin + Cyrillic + Ө Ү + ₮ U+20AE, built with pyftsubset from the Inter release, see §6c), `inter-display-750.woff` (the Inter Display variable instanced at wght 750, same subset) and `jetbrains-mono-500.woff` (the site's mono file re-saved as WOFF).
- Internal links (Oct 2026): an article page is never a dead end. A visible breadcrumb (`Нүүр › topic › place`, the same items as its `BreadcrumbList`), the people chips link to `/officials/<id>` when the short name belongs to exactly one active MP (`linkPeople` in `src/lib/officials/links.ts`, shared names never link), and a "<topic> · сүүлийн мэдээ" panel lists the 5 newest stories of the same effective topic outside its cluster (`getTopicNeighbours` in queries.ts) with a link to the hub. Story headlines in `StoryList` are `<h2>` (lead) / `<h3>` (rows), so `/` and topic pages have a real outline.
- Archive and source hubs (Oct 2026): `/archive/<yyyy-mm-dd>` (`getDayArchive`: every published story of that Ulaanbaatar day, no importance cut-off, grouped by topic, undated rows last as "found that day"; prev/next = the nearest days with stories; `CollectionPage` + `ItemList` + `BreadcrumbList`; the last 14 days prerendered, older ones on demand; an invalid or empty day is 404 + noindex) and `/archive` (last 60 days with counts, `getArchiveDays`). Day keys and labels come from `src/lib/archive.ts` (`ubDateKey`, `ubDayBounds`, `archiveDateLabel` with the day's genitive "26-ны" / "21-ний"). `ArchiveLinks` (last 7 days) sits under the feed on `/` and every topic page, the footer links "Архив". `/source/<domain>` (`getSourceHub`, newest 40, prerendered for sources with stories, noindex while empty; the `<title>` carries the domain, "Сангийн яам (mof.gov.mn) — мэдээ, шийдвэр", because people search "mpr gov", "emd gov") is linked from the article's source name and the hub list at its end, and from `/sources` only when it has published stories (`visibleCount`). The sitemap lists the last 180 archive days and every source with stories.
- Topic pages are one-subject pages ("content silos"): `src/lib/topic-seo.ts` gives every feed filter the phrase people search for (visible `<h1>` "Улс төрийн мэдээ", `<title>` "… — өнөөдрийн шинэ мэдээ"), a true 1–2 sentence intro (also the meta description) and its common Latin spellings ("uls turiin medee"), shown once in visible text; `CollectionPage` + `BreadcrumbList` JSON-LD. Never hidden keyword lists (penalised). The home `<title>` carries the Latin brand "iltodmedee" (Google suggested "altamed" for it in Oct 2026).
- Thin pages (Oct 2026): `isThinArticle` (`src/lib/seo.ts`, unit-tested) = importance below `FEED_MIN_IMPORTANCE` (25, also defined there and imported by queries.ts) AND no cluster AND no ₮ amount AND not legalinfo.mn; null importance is never thin. Such articles get `robots: noindex, follow` and stay out of `sitemap.xml` and `news-sitemap.xml` (`indexable` in `src/lib/story-rules.ts`, the SQL twin of `isThinArticle`); RSS, the archive and source hubs still list them. ~36 % of stories in Oct 2026 (mostly opendata.gov.mn listings and gov.mn event notices). `/method#importance` says so.
- Never target another outlet's name: "unenmedee" is the Ünen newspaper's brand (unenmedee.mn); UNENMEDEE is only this repository's name.
- Search Console: set `NEXT_PUBLIC_GOOGLE_SITE_VERIFICATION` (and optionally `NEXT_PUBLIC_BING_SITE_VERIFICATION`) on Vercel, then submit `/sitemap.xml` and `/news-sitemap.xml`.
- Off-screen blocks use `content-visibility: auto` (Nov 8 2026: on a phone half the home page's ~1 000 elements sit two screens down; Chrome at 4x CPU spent ~170 ms in style and ~230 ms in layout on load, ~112 / ~140 ms with it): story rows from the fourth (`.story-rows > li`), the archive links (`.cv-auto`) and the footer (`.cv-footer`), each with a `contain-intrinsic-size` near its real height. `scripts/check-layout.ts` forces `content-visibility: visible` before measuring, or an overflow down the page would go unseen. Measure a speed change with `npm run perf -- <url> [--css "…"]` (`scripts/perf-loop.ts`: Chrome's own style, layout and script time at 4x CPU, median of 5 loads; `--css` injects a rule on the live page so an idea is measured before it is built), not a single Lighthouse run.
- Reader progress (GLOSSARY.md: counted read, XP, level, badge, tier; grilled with the owner Nov 8 2026): kept only in the reader's browser under `iltod-progress` (`src/lib/progress.ts`, pure and tested; `src/lib/progress-store.ts` reads, writes and announces it), no accounts and nothing sent. The article page's `ReadMeter` counts a read after 15 s on screen and past half the story, a facts view after the `data-progress="facts"` panel is half on screen for 3 s, a source visit on a click of `data-progress="source"`; the digest counts a finished edition. Hard on purpose: one count per story, at most 20 reads / facts / sources a day, the tenth level at 36 000 XP (about a year of daily reading). The back-to-top button is the meter: closed, its ring shows the way to the next level (teal) or, on an article, the way to a counted read (yellow), "+N" for two seconds when XP arrives, a note on a new level or badge, and a red dot while a badge is unseen; it shows from the start on article pages. A tap opens the dial (the owner's pick, Nov 8 2026, replacing "a tap goes to the top"): the next badge, the level, the streak strip, and «Дээш буцах» nearest the thumb, its cards a staircase narrowing toward the thumb (`DIAL_WIDTHS`); a scrim tap, Esc, a swipe or the wheel closes it (gestures, not the scroll event: layout shifts move the scroll position too).
- Badges (`src/lib/badges.ts`, pure and tested): 47 in nine collections (Эхлэл, Дараалсан өдөр, Унших, Шалгах, Мөнгө, Төр ба иргэн, Зуршил, Нээлт, Нууц), four tiers хүрэл / мөнгө / алт / ил тод (+25 / +50 / +100 / +250 XP) or one step (Эхлэл +25, Нууц +100); the thresholds the owner agreed are in `tests/badges.test.ts`. Badge ids live in readers' browsers: append, never rename or reuse one. `award` stamps each new tier with its Ulaanbaatar day and never takes one back. The rules load lazily (`checkBadges` imports `src/lib/badge-award.ts` after a change, the dial imports `dial-badge.tsx` with `next/dynamic`), never with a page. `PageMeter` (layout, one tick a second while visible) counts section pages read 15 s (`pageOf`: /budget, /promises, an MP page, an archive day…), `data-progress-item` rows seen 2 s (tender rows) and `data-progress-flag` clicks (the information-request letter). The streak is Reddit's ladder (the owner's pick): ten one-step badges `streak-<days>` (Оч 3 … Домог 1 000), each with its own night-sky art and tier rim and XP; the four-tier `streak` badge was retired and its id is never reused. `/amjilt` (noindex) shows the level, the streak (a big number, `streakWindow`'s two days back / today / two ahead, then the ladder grid with dates and a bar on the next one), the closest badges and every other collection; every badge is the same tile (`BadgeTile`: art, a two-line name box, one short line, an always-present bar slot, so each grid row lines up; the owner: "symmetrical, like Reddit"), locked ones silhouettes, secret ones "???" until earned; a tap opens `BadgeDetail` under the grid with how to earn it and each tier's count or date. No Цагаан сар badge: its date moves and sources disagree, so the holiday secrets are Наадам and Шинэ он.
- History import (the owner, Nov 8 2026: loyal readers must not start at zero): once per browser (`imported` flag), `importHistory` turns the stories it already marked read (`iltod-read`, its last 600) into counted reads with their XP, and the daily digest streak (`iltod-streak`) into the streak and best streak; `BackToTop` triggers it when the page is idle, and the toast says how many stories counted. Restore code (`src/lib/progress-code.ts`, tested): «Кодоо хуулах» on /amjilt writes the whole progress as `ILTOD1.` + base64url(deflate-raw(JSON)) (about 1 000 characters for 240 stories); «Код оруулах» decodes it with an inflated-size cap and `sanitizeProgress` (every field type-checked, also on every storage read) and replaces this browser's progress after a confirm. `saveProgress` asks `navigator.storage.persist()` once a page view. While the install strip shows, it sets `--install-lift` to its height and the back-to-top button rises above it.
