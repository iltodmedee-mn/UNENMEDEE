Rules for this area, moved from `CLAUDE.md` with its section numbers. Keep each rule here, in one place; the reason behind a change goes to `docs/HISTORY.md`.

## 7. PWA & push notifications
- `src/app/manifest.ts` + `public/icons/*` + `src/app/apple-icon.png`: installable app. `public/sw.js` handles push, notification clicks and an offline page; it never caches pages (`/sw.js` is served `no-store`, see `next.config.ts`).
- `src/components/pwa/*`: 🔔 header button and the phone install banner (4 s after load; until the app is installed it comes back `REASK_MS` = 5 min after every ✕ or after 20 s ignored, across pages and reloads, only in a visible tab and never while a dialog, menu (`[data-popover]`) or input is active; rules in `src/lib/install-ask.ts`, tested). Installed = never: Android Chrome stops firing `beforeinstallprompt` (not eligible; a cancelled prompt counts as ✕), standalone never shows it, and Safari cannot see a home-screen install, so the iPhone steps sheet has "✓ Нүүр дэлгэцэнд нэмчихсэн" (`iltod-app-installed`) and opening the steps rests the strip for a day. An inline `<head>` script keeps a `beforeinstallprompt` that fires before the chunks load (`window.__iltodBip`). The bell always opens its sheet first (what is sent + "Асаах"); only that button asks the browser for permission, because browsers that hide the prompt made a bell that asked directly look dead. iOS only allows push in an app added to the home screen, so the UI explains that first. Sheets are portaled to `<body>` (the sticky header's backdrop-filter traps `position: fixed`).
- Subscriptions: `push_subscriptions` via public server actions in `src/app/push-actions.ts` (zod + push-service host allowlist; only canonical endpoint strings, `u.href === endpoint`, so web-push cannot parse a stored endpoint differently). The VAPID key pair lives in `app_settings` (read by GitHub Actions through DATABASE_URL); the public key is also `NEXT_PUBLIC_VAPID_PUBLIC_KEY` on Vercel. Never regenerate the pair: subscriptions are bound to it.
- `npm run push:send -- --mode news` (after ai:process): importance >= 70 (`PUSH_IMPORTANCE_MIN`) or risk flag, published < 24 h, dated and AI-summarized (`postable`, like social posts and videos; an undated old page found today used to go out as new), `notified_at` null (`selectPushCandidates`, `src/lib/push/news-selection.ts`); ONE notification per run (top story + "+N чухал мэдээ"): bursts were partly rejected by Apple. `--mode digest` after each digest. Failures are logged with status and body; dead subscriptions (404/410) are deleted. The 🔔 sheet has a "test notification" button (`sendTestPush`, own endpoint only, 1/min).
- Failure accounting (`classifyPushFailure` in `core.ts`): 404/410 delete the subscription; another 4xx (VAPID mismatch, bad key) counts towards `MAX_PUSH_FAILURES` (5); 429/5xx/network errors never count (an outage must not delete every subscriber), and neither does a run where most subscriptions got a 4xx (`isSystemicFailure`: our VAPID/payload problem, logged as `::error::`). `ensureVapidKeys` refuses to generate a pair while subscriptions exist (restore `app_settings` instead). `--mode digest` looks back 12 h and claims the edition atomically before sending (`advanceMarker` in `src/lib/claims.ts`: an upsert that only moves `push_last_digest_id` forward), so the pipeline and news-digest.yml (separate concurrency groups: GitHub drops a pending run when another queues in the same group) never both send it; a run where every send failed gives the claim back. News and mention alerts are marked notified only when something was delivered or nobody is subscribed. `npm run health` also reports subscriptions with 3+ consecutive failures.

## 7b. Facebook page
- `npm run social:post -- --mode news|digest` (`--dry-run`; `scripts/post-social.ts`, `src/lib/social/facebook.ts`) posts to the ИЛ ТОД МЭДЭЭ page via Graph `POST /{page-id}/photos` with our hook card (`url` + `caption`; `/feed` `message` + `link` only without an image; the token only in the POST body; `FB_GRAPH_VERSION`, default v26.0). Digest: the newest edition < 12 h old. News: published < 24 h, dated, AI-summarized (no fallback), importance >= `FB_IMPORTANCE_MIN` (75) or risk flag, one per cluster, `FB_NEWS_PER_RUN` (1) / `FB_NEWS_PER_DAY` (4).
- A platform's request limit (Graph codes 4, 17, 32, 613 or HTTP 429, `isRateLimited` in `outcome.ts`) is a `::warning::`, not a failed step: the reservation is freed and the next run tries again (Nov 7 2026: Instagram's "Application request limit reached" turned the pipeline red).
- `social_posts` (platform, kind, ref_id unique) is reserved before the call and deleted only when the platform clearly refused the post; a timeout/dropped connection or a 2xx answer without a readable post id (`UnknownOutcomeError`; `outcomeUnknown`, `src/lib/social/outcome.ts`) or a DB error after publishing keeps the row (`post_id = 'unknown'`, `::warning::`, check by hand), so nothing posts twice. Container polls (Threads 10, Instagram 12 checks) throw instead of publishing an unfinished container. Links use `PRODUCTION_URL` (Actions has no Vercel URL). Steps run after the push steps when any of `FB_PAGE_TOKEN`, `THREADS_TOKEN`, `INSTAGRAM_TOKEN` is set; `vars.FB_PAGE_ID` is optional (a Page token's `GET /me` is the page). `resolveFacebookPage` detects a user token (only users have `/me/accounts`; Oct 2026 the secret held one and every post failed with "(#200) publish_actions is deprecated") and posts with that Page's own token, with a `::warning::` to replace the secret. Setup (never-expiring Page token): `docs/FACEBOOK.md`. Never put the token in chat, logs or files.
- Threads (`src/lib/social/threads.ts`): the same digests and stories go to Threads through `graph.threads.com` (IMAGE container with the hook card and the link in the text, TEXT + `link_attachment` only without a card; wait for `FINISHED`, then `threads_publish`; ≤ 500 characters with emoji and U+FE0F counted as UTF-8 bytes, cut at whole graphemes by `cut()`). The `THREADS_TOKEN` secret only seeds the token: the live long-lived token sits in `app_settings` key `threads` and is refreshed after 7 days (`th_refresh_token`; 60-day expiry); a new secret value (different sha256 `seed`) replaces it, and a removed secret turns the platform off (`currentState` returns null; the stored token is no longer used or refreshed). Each platform has its own `social_posts` rows and limits; one failing never stops the other.
- Instagram (`src/lib/social/instagram.ts`, Instagram API with Instagram Login on `graph.instagram.com`): an image container from our own JPEG card `/ig-image?d=<digest id>|a=<slug>` (1080×1350, `hookCard` in og.tsx; Instagram accepts only JPEG from a public URL, next/og renders PNG, so the route re-encodes with the pure-JS `fast-png` + `jpeg-js`, sharp stays out of the functions), poll `status_code` until `FINISHED`, then `media_publish`. Error 9007 "Media ID is not available" (`MEDIA_NOT_READY`) on the status read counts as still processing and on `media_publish` is retried `PUBLISH_RETRIES` (3) times 5 s apart: Oct 28 2026 it came back on the first status read right after a successful create, and one article reached Facebook, Threads and Discord but not Instagram (the next run posts it there, since selection is per platform). Captions are plain text (≤ 2200, links not clickable: "холбоос bio-д"). `INSTAGRAM_TOKEN` seeds the 60-day token kept in `app_settings` key `instagram` and refreshed weekly (`ig_refresh_token`); token handling is shared with Threads in `token-state.ts`. Publishing works for the account added as Instagram tester while the app is unpublished.
- Hook style (all platforms): every post carries our 1080×1350 card `/ig-image` (`hookCard(FeedCard)` in og.tsx, Nov 2026 poster look the owner chose after noorog.mn / mogul.plus, the same frame as the weekly quiz (`posterCard`): red full bleed with film grain, "logo | ШИНЭ МЭДЭЭ / АНХААРАХ МЭДЭЭ / ӨГЛӨӨНИЙ ТОЙМ · 07:05" with the day or story count on the right, the topic as a yellow kicker, the headline in huge Oswald 700 capitals with its first number + units + next word in yellow (`hookWords`, `src/lib/social/hook.ts`, rule-based, never adds a claim; a year followed by "он/оны/онд" is skipped, brackets are ignored), "→ who: change" / why it matters / the first summary sentence, the ₮ amount on a yellow pill with its per-person share, the AI fact/PR bar, a digest's next three headlines numbered 02–04, "ILTODMEDEE.MN" and the source as a credit bottom right; a giant faint "₮" or the logo mark where those pages put a photo). Facebook posts are photo posts (`/{page}/photos`, `url` + `caption`, link in the text; `/feed` link post only without an image), Threads posts are IMAGE posts with the link in the text. Texts lead with the hook: "⚡ headline" (🚨 for risk), "👉 why it matters", then more headlines/source and the link. No photos of people, no AI images, no invented quotes.
- Whole story in the post (Oct 2026 mission audit: posts were "headline + link" and most readers never tap): `articlePost` (Facebook, reused by Telegram) and `instagramArticlePost` print the plain headline, "Танд хамаатай юу?" (`impactLines` in `src/lib/social/story-lines.ts`: who / what changes / from when / what to do, only the grounded fields), the summary, up to two short facts (`keyFacts`: ≤ 160 chars, not a repeat of the summary, not a bare amount), the ₮ amount + per-person share, and `factShareLine` ("📊 Баримт 72% · Пи-ар 28% (AI-ийн үнэлгээ, буруутгал биш)"). Threads uses "👤 who: change" instead of the summary sentence when it exists; Discord adds it above the quote. `post-social` passes `reader_impact` and `fact_vs_spin.facts`. The `/ig-image` article card's sub line is "who: change" when known, its money line adds the per-person share, and `hookCard({ fact })` draws the site's fact/PR bar labelled "AI-ийн үнэлгээ, буруутгал биш" (not for no-AI fallback rows). `hookWords` reads "₮600,000" (currency first, as the plain headlines write it) as the number to highlight.
- Per-person share (`src/lib/per-person.ts`): a story's largest ₮ amount ≥ 1 тэрбум divided by Mongolia's residents (`POPULATION`: 3,425,162 at the end of 2025, NSO table `DT_NSO_0300_001V2`; the watchdog says when NSO publishes the next year, from the `population` snapshot), worded as plain division ("👤 3.43 сая хүнд хуваавал ≈ 14 200₮ / хүн", never "you pay") and rounded (10 / 100 ₮, "сая" above a million). Facebook (and Telegram, which reuses its text), Instagram and Discord story posts carry it.
- Hashtags (`src/lib/social/hashtags.ts`, by the site's own topic rule `topicFor()`: aimag/district sources `local`, opendata `data`, else the AI topic with the domain as fallback): Facebook 3 (`#ИлТодМэдээ` + one topic tag + `#Монгол`), Threads exactly one (it links only one topic tag), Instagram ≤ 10 (brand, topic tags, `#мэдээ #Монгол #Mongolia #mongolianews #Улаанбаатар #шинэмэдээ`). `.github/workflows/social-post.yml` (manual: `mode` news|digest, `dry_run`) posts at once with the pipeline's secrets; `social_posts` still prevents doubles. A failed Threads/Instagram refresh is a `::warning::` while the stored token is under 45 days old and `::error::` + a red step after (`refreshSeverity`, `REFRESH_ERROR_AFTER_DAYS`); a Facebook Page token that `resolveFacebookPage` rejects also turns the step red.
- Telegram (`src/lib/social/telegram.ts`): the bot (admin of the public channel) posts the same digests and stories with Bot API `sendPhoto` (our `/ig-image` card, the Facebook text as caption cut to 1024 by `cut()`), `sendMessage` without a card. `TELEGRAM_BOT_TOKEN` secret + `TELEGRAM_CHAT_ID` variable ("@channel"); the token sits in the Bot API URL path, so URLs are never logged and errors have it replaced by `***`. Own `social_posts` rows (platform `telegram`).
- Discord (`src/lib/social/discord.ts`): the bot posts the digests and stories to our server's announcement channel through the REST API (`POST /channels/{id}/messages`) as a short card for younger readers (`discordArticlePost`/`discordDigestPost`: bold headline, the summary as `>` quotes, the amount and its per-person share in bold, the AI's neutrality and risk scores as 5-block emoji meters labelled "AI-ийн үнэлгээ, буруутгал биш", numbered digest headlines, no hashtags; `bold()` strips `*` from scraped text), our link wrapped in `<…>` so only the `/ig-image` card embed shows, `allowed_mentions: { parse: [] }` so scraped "@everyone" pings nobody, ≤ 2000 characters), then crossposts it to every server that pressed Follow (a failed crosspost is a `::warning::`, not a failed post). REST only from Actions, no gateway connection, so nothing is hosted. `DISCORD_BOT_TOKEN` secret (Authorization header only) + `DISCORD_CHANNEL_ID` (variable or secret, the bare id or the channel URL: `discordChannelId` takes the last 17–20 digit number); own `social_posts` rows (platform `discord`). Setup: `docs/FACEBOOK.md`.
- Launchpad campaign (Nov 2026, `src/lib/social/promo.ts`, `tests/promo.test.ts`): `npm run social:post -- --mode promo` (pipeline step after the video post) posts the day due of `PROMOS`, 3–7 November 2026 at 19:00 Ulaanbaatar (`PROMO_WINDOW_H` 4), as a Reel on Facebook, Instagram and Threads: `public/promo/launchpad-d<n>.mp4` (each day its own short video, narration not the post text) with that day's text, every text opening with the launchpad.mn link. `social_posts` kind `promo`, ref = day; refused reels retry like videos (`VIDEO_MAX_TRIES`). No entry after 7 November, so the step is a no-op from then on; the regular daily videos are untouched. Delete the module, step and files once the campaign is over.
- Daily quiz (`src/lib/social/quiz.ts`, `npm run social:post -- --mode quiz`, news-digest.yml, at most one per `QUIZ_EVERY_H` 20 h): a Discord poll from the most important story of the last 3 days whose headline names a ₮ amount (≥ 100 сая) that is also one of its extracted ₮ amounts (`headlineAmount`; so "тэрбум мод" or dollars never qualify). The headline with the amount masked is the question ("Эрчим хүчний салбарт ❓ төсөв баталлаа. ❓ хэд вэ?"), the options are the amount ÷10, ÷3, ×1, ×3 with the right answer's significant digits (`roundLike`, so precision never gives it away), its position shifts with the story id, letter emojis 🅰️🅱️🇨🇩, 24 h. The answer is a `||spoiler||` with its per-person share and the story link. Rule-based, no AI; `social_posts` kind `quiz`.
- Weekly quiz carousel "7 хоногийн тест" (`src/lib/social/weekly-quiz.ts`, `tests/weekly-quiz.test.ts`; Nov 2026, the owner's pick over a digest carousel): `npm run social:post -- --mode weekly-quiz` (pipeline step, every 30 min, a no-op without platform calls unless due; the manual `social-post.yml` mode posts it at once) posts on Sunday from 19:00 Ulaanbaatar (`isQuizTime`, a late run until 06:00 Monday) a carousel of up to 5 questions (`QUIZ_QUESTIONS`, at least 3) from the last 7 days' published, AI-summarized, dated stories: the display headline with its ₮ amount hidden (`maskAnswer`: the amount must be one of the story's `amounts_mnt`, be written with ₮ / төгрөг, so "164 сая кВт.ц" stays visible, and not appear twice; the ₮ word and its case ending stay, "❓ ₮-ээр"), ≥ 10 сая (`WEEKLY_QUIZ_MIN`), most important first, one per cluster, never a headline that weighs or accuses (`weighsOrAccuses`). Four ascending options (`quizOptions`: the answer and multiples of it at its own precision via `roundLike`), the right one one place further each question. The quiz is stored once in `app_settings` key `weekly_quiz` (every platform and run posts the same questions); the next evening from 19:00 (`answersDue`: a later Ulaanbaatar day than that platform's quiz post, within 72 h) the answers card with each letter, amount, headline and per-person share as plain division. Facebook: an album (`publishAlbum`: unpublished `/photos`, then one `/feed` with `attached_media`); Instagram `publishInstagramCarousel` and Threads `publishThreadsCarousel` (item containers, each waited for, then the CAROUSEL); the answers are one image post. `social_posts` kinds `wquiz` / `wquiz_ans`, ref = ISO week, refusals retried at most `VIDEO_MAX_TRIES` like videos. Cards: `/quiz-image?w=<yyyyww>&n=<0…n+1|a>` (`quizCard` in og.tsx, JPEG through `src/lib/jpeg.ts`, shared with `/ig-image`; read uncached from `app_settings`, only the stored week renders, the answers card only 18 h after the quiz was made) in the full-bleed look of noorog.mn / mogul.plus the owner pointed to (red with film grain from a generated noise PNG, logo | series label, dates top right, Oswald 700 condensed capitals in yellow and white, a giant faint glyph instead of a photo, swipe arrow, credit block; the answers card is yellow). Oswald (SIL OFL, `src/assets/fonts/OFL-Oswald.txt`) is subset like the other card fonts (Latin, Cyrillic with Ө Ү, ₮; `oswald-700.woff`, 25 KB). Captions list every question with its options; no engagement asks.
- Weekly top list (`src/lib/social/weekly.ts`, `npm run social:post -- --mode weekly`, news-digest.yml; posts only on Monday in Ulaanbaatar, once per ISO week = `social_posts` kind `weekly`, ref `yyyyww`; the manual workflow passes `--any-day`): last Monday–Sunday's biggest ₮ amount (with its per-person share and story), the cluster the most distinct sources reported, the active MP named in the most stories (exact `short_name`, shared names left out, ≥ 2 stories, worded "тоо, үнэлгээ биш"), legalinfo.mn acts, totals and AI-high-risk count. Discord gets bold and `<links>`, Facebook (link post) and Telegram plain text, Threads a ≤ 500-byte short version; Instagram is skipped (needs an image). Rule-based, no AI.
- Discord slash commands (`src/lib/social/discord-interactions.ts`, route `src/app/api/discord/route.ts`): Discord POSTs `/toim` (latest 12h digest), `/haih ug:` (`search()`, top 5) and `/aimag ner:` (autocomplete over `PLACES`, `getPlaceFeed(domains, 5)`) to `/api/discord` (the app's Interactions Endpoint URL), so nothing is hosted. Every request needs a valid Ed25519 signature over `timestamp + raw body` for `DISCORD_PUBLIC_KEY` (Vercel env var; missing → 404, bad signature → 401, as Discord requires); PING → PONG, autocomplete answers at once, commands answer DEFERRED and the reply is edited in `after()` through the interaction webhook (`PATCH /webhooks/{app}/{token}/messages/@original`, no bot token). Replies: our stories only, masked links `[title](<url>)` without previews, no mentions. Commands are global, for guild and user installs (`integration_types: [0, 1]`, `contexts: [0, 1, 2]`), registered by `npm run discord:commands` (manual `discord-commands.yml`, PUT with the bot token). Setup: `docs/FACEBOOK.md`.
- Messenger + Instagram DM bot (`src/app/api/messenger/route.ts`, `src/lib/social/messenger.ts`): Meta's webhook calls `/api/messenger`; GET answers the `hub.verify_token` check, POST is dropped unless `X-Hub-Signature-256` (HMAC of the raw body bytes with the app secret) matches; `verify_token` is compared in constant time (`sameSecret`). The route answers 200 at once and sends replies in `after()` (a slow search made Meta redeliver and the reader got the answer twice); a redelivered `mid` is answered once per instance (`seenOnce`, 500-entry LRU); at most `MAX_REPLIES_PER_DELIVERY` (25) per POST. Webhook objects `page` (Messenger, page token, graph.facebook.com) and `instagram` (DMs, the Instagram token from `app_settings` `instagram`, graph.instagram.com) are answered alike through `/me/messages`; a body is accepted when it is signed with the app secret or the Instagram app secret (`igAppSecret` in the settings JSON, else the `IG_APP_SECRET` env var, else `app_settings` key `instagram_app_secret`). Replies use our own data only, no AI: "тойм" → latest 12h digest (5 headlines + links), greetings/Get Started → help, anything else → top 3 `search()` results with links. Messages are not stored in the database (the search text is a `'use cache'` key for up to an hour; `/privacy` says so). Secrets (`pageId`, `pageToken` with `pages_messaging`, `appSecret`, `verifyToken`) come from the Vercel env var `MESSENGER_SETTINGS` (the same JSON) or else `app_settings` key `messenger` (cached 5 min per instance). Own-page messaging needs no App Review.
