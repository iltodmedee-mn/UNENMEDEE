# AI pipeline

Rules for this area, moved from `CLAUDE.md` with its section numbers. Keep each rule here, in one place; the reason behind a change goes to `docs/HISTORY.md`.

### AI pipeline (`src/lib/ai`)
- `router.ts`: provider chains. `DEFAULT_CHAINS`: tier1 = Groq → Gemini → NVIDIA → Requesty → OpenRouter → Z.ai → DeepSeek → Ollama; tier2 = Grok → Gemini → Groq → NVIDIA → Requesty → OpenRouter → Z.ai → DeepSeek → Ollama; with a billed Gemini key `placeGemini` moves Gemini behind the free providers, so the effective tier-1 order is Groq, NVIDIA, Requesty, OpenRouter, Z.ai, Gemini, DeepSeek, Ollama. An `AI_TIER1_CHAIN` / `AI_TIER2_CHAIN` variable is used exactly as written (no `placeGemini`). Every setting's place and precedence: `docs/CONFIG.md`. Tier-1 calls rotate the leading free providers (`spreadFree`: Groq, NVIDIA NIM, Requesty, OpenRouter take turns; Z.ai GLM Flash is only the free overflow before Gemini, its Mongolian was weaker on the sample; `AI_CONCURRENCY` 3), because a fixed order sent everything to Groq and left NVIDIA's free quota unused; with only three free providers 38 % of the bulk calls overflowed to the billed Gemini key (Oct 2026). Free-only locks: OpenRouter calls only `:free` model ids (`openRouterModel`, default Nemotron 3 Ultra: the free Gemma endpoints answered 429; the account needs "free endpoints that may train" ON and Zero Data Retention OFF, else 404; 50 calls/day, `OPENROUTER_DAILY_MAX_CALLS` 45), Z.ai only `-flash` GLM models (`zaiModel`; FlashX bills), Mistral is opt-in only (not in the default chains): its free API has answered every request with 429 since Aug 2026 (paying accounts only), so `isPaid` treats it like Requesty (always inside the USD budget, even without `MISTRAL_PRICE_IN/OUT`). The manual `maintenance.yml` task `ai-sample` runs the Mongolian sample through each free provider alone to judge a new key or model. Gemini: a key from a Google project WITHOUT billing (`GEMINI_FREE_TIER=true`) is free and keeps its place and the "-latest" models. A billed key (Oct 2026: the owner's "Paid 1" project was charged while the logs said $0) moves behind the free providers (`placeGemini`), uses only the cheapest text model a new key may call, `gemini-3.1-flash-lite` ($0.25/$1.50 per 1M, `GEMINI_BILLED_MODEL`; `gemini-2.5-flash-lite` answers 404 "no longer available to new users" since Oct 29 2026; `geminiModel()` ignores a `GEMINI_MODEL`/`GEMINI_DEEP_MODEL` override that is not Flash-Lite), is priced per model (`geminiModelPrice`) and counts against the USD budget. Image, video and speech models are refused (`isTextModel`): the site never generates images. The one deliberate exception is the video narration (`src/lib/video/tts.ts`, §7c), a speech model called on its own path with the same guard and logging. JSON mode + zod validation + one repair retry; every prompt ends with `SCRIPT_RULE` (Mongolian only in Cyrillic, through `DATA_GUARD`) and a reply whose Latin letters outnumber its Cyrillic ones fails validation (`isLatinText`, `src/lib/script.ts`: Tier 1 summary + facts, Tier 2, cluster synthesis, digest intro and headlines; reader headline and impact fields become null), the watchdog's integrity line counts such published rows; one retry after a 429 (each retry passes the budget guard again). The OpenAI client runs with `maxRetries: 0`: the router owns retries (the SDK's default of 2 tripled 429s and timeouts). A provider that fails `PROVIDER_TRIP` (2) transport calls in a row (timeout, 5xx, auth, network, an answer without `choices`; not a 429, not invalid JSON, not a request-specific 400/413/422 such as Groq's "Request too large" for one big digest prompt; a 400 naming a retired or unknown model, `isRetiredModel`: "decommissioned", "no longer available", "does not exist", "no endpoints", does trip it, because free model ids are retired every few months and such a 400 otherwise failed every call silently) is skipped for `TRIP_RESET_MS` (30 min; `tripped`, `resetProviderTrips()` in tests; Gemini's 400 "API key not valid" trips it too, `isBadKey`) and every such failure prints `[ai] <provider> failed …` to the workflow log, because a call that returns no tokens is not in `ai_usage_logs`: on Oct 28–29 2026 NVIDIA NIM timed out on every call (180 s) invisibly and every third article waited 4 min; its timeout is now 60 s. The repair attempt doubles `maxTokens` (cut-off JSON is the usual invalid reply). `ai:process` parks an article (`ai_error`) when `shouldPark(attempts)` (`fallback.ts`): two unusable replies, or every provider that answered gave one; outages alone never park, and neither does a bad reply whose repair the budget stopped. Only published rows are analysed or clustered (`is_published=false` rows, kept for dedupe, cost 44 % of the calls before Oct 2026). Articles that got the extractive fallback are offered to the AI again (`RETRY_FALLBACK_PER_RUN` 10 per run, newest first, `RETRY_FALLBACK_DAYS` 3); `processArticle` clears `summary_fallback`. Every call (success or failure with tokens) is logged with its USD cost via `usage-log.ts`; a provider-reported cost (Requesty) wins over the price table.
- `limits.ts`: budget guard checked before every call. Paid providers (price > 0, and Requesty always) stop at `AI_MONTHLY_BUDGET_USD` ($3) / `AI_DAILY_BUDGET_USD` ($0.30); every provider has `<PROVIDER>_DAILY_MAX_CALLS` (Grok 5) and optional `<PROVIDER>_RPM` throttling. Free providers keep working when money runs out. Never call a provider without passing a guard in production code (`dbBudgetGuard(db)`).
- Token budget: Tier-1 input is cut to 4,000 chars, Tier-2 to 8,000; opendata.gov.mn datasets are summarized by rules (`ruleBasedAnalysis`, 0 tokens).
- `analyze.ts`: `analyzeArticle` (pure, used by admin), `processArticle` (writes DB), `assignCluster`/`refreshCluster`.
- `risk_flag` is derived from `risk_score >= 65`, never trusted from the model. Regex MNT amounts are merged into entities.
- Clustering: stem Jaccard + entity overlap, threshold 0.45, cross-source only, 7-day window on the publication time (`published_at`, never `created_at`: an old notice found late joined a new one, cluster 6 = #91/#1372 in Nov 2026; `outsideWindow` also keeps any two rows more than 7 days apart), published rows only; synthesis only at growth milestones. A same-headline channel (`SAME_HEADLINE` 0.8 title-stem Jaccard, ≥ 3 stems, ≥ 0.3 overlap of the summaries alone, and a shared person/organisation when both have entities) joins two sites posting one story with differently worded AI summaries while identical generic headlines about different events stay apart (`tests/fixtures/cluster-pairs.json`, real Oct 2026 pairs). `ai:process` clusters a whole run at once (`assignClusters`: one pool load, every row of the 7 days): the old per-article pool was capped at the 500 newest rows (~2 days) and found 3 clusters in a week. `npm run ai:process -- --recluster` reclusters the last 7 days; run it from the manual `maintenance.yml` workflow (also `refetch-dates`: `npm run db:repair-dates -- --refetch` re-dates the last 14 days' undated rows with the current extractor).
- Reader's view (Oct 2026 mission audit: headlines stayed in government language, 64 of 586 over 120 characters, and nothing told a reader whether a story touches them): Tier 1 also returns `reader_title` (≤ 80 chars, decision/number first, no protocol phrases) and `impact` {who, change, when, action} ("Танд хамаатай юу?"), stored as `articles.reader_title` / `reader_impact` (migration 0018). `src/lib/ai/reader-view.ts` grounds them: every number must be a whole number in the title + text + publication date (Ulaanbaatar day), or, with a scale word on either side, within 5 % of a source amount (`numbersGrounded`; the old digit-substring check found "5" inside "2026"; month numbers before "сар" are not checked), placeholders ("тодорхойгүй", "null") become null, a headline equal to the original, all-caps or outside 12–100 chars is dropped, and an impact without `change` or `action` is null. Queries show `coalesce(reader_title, title)` (`DISPLAY_TITLE`; `ArticleListItem.sourceTitle` is the government's headline when ours differs, printed under the article `<h1>` as "Эх гарчиг" and as JSON-LD `alternativeHeadline`); push, social posts, RSS and the OG cards follow. The ceremony check, digest candidates, search and /changes keep the source title. `ReaderImpactBlock` (`reader-impact.tsx`, an `AIMessage`) sits above the summary on the article and in an opened story; a collapsed row's teaser becomes "Танд · <who>: <change>". A ceremonial headline with no impact gets the rule-based "Протокол" chip and `ProtocolNote` (never the model's call). `npm run ai:reader` (pipeline, after ai:topics, `--limit 64`) fills last month's feed stories 8 per call from headline + summary + facts with the same grounding (`reader-batch.ts`, `scrape_meta.reader_attempts` ≤ 2); an answer that shares no 5-letter word stem with its own story is dropped (a model that shifted its list by one). `/method#reader` explains it.
- Press coverage (`src/lib/press`, Oct 2026 mission audit: 4 clusters in two weeks and no way to see whether the independent press wrote about a decision): `npm run press:sync` (pipeline, after ai:reader; `--dry-run`) reads `OUTLETS` (`outlets.ts`: ikon.mn RSS, news.mn's customised WordPress API (no link/date: URL `https://news.mn/r/<id>/`, dated when found), sonin.mn RSS) through `politeFetch` (robots + 8 s), stores headline + link only in `press_items` (no text, no description, 45 days, not in backups) and links them to the last 7 days' published stories in `press_links` (migration 0019, RLS). `matchPress` (`match.ts`, unit-tested with real Oct 2026 headlines) = TF-IDF cosine (smoothed IDF, 5-letter stems) of our headline ×2 + first summary sentence against the press headline alone, ≥ `PRESS_MATCH_MIN` (0.45, calibrated: headline + lead matched weather notes to each other, 0.43 was two different conferences), within −2/+5 days, and `namesClash` rejects two headlines naming different people (one MP's "Нээлттэй парламент" vs another's). Left out on purpose: montsame.mn (403, not worked around), gogo/unuudur/eagle/isee (no feed), ugluu.mn (reprints parliament.mn verbatim). The article page's `PressPanel` ("Хэвлэлд") lists them; StoryList shows "📰 N хэвлэлд" (`pressCount` subquery in `listColumns`). `isPressBlindspot` (importance ≥ 70, ≥ 24 h old, published after `PRESS_TRACKING_FROM`, dated, no link, and every outlet in `OUTLETS` gave a new headline in the story's first 48 h, so a broken feed never reads as "not found"; computed inside the cached `getArticleBySlug`) shows a neutral "бидний уншдаг 3 хэвлэлд … ижил гарчиг олдсонгүй", never "the press ignored it". Migrations 0018/0019 are idempotent (`IF NOT EXISTS`) because the columns/tables were created by hand right before the deploy that reads them.
- Ceremony cap (`src/lib/ai/ceremony.ts`, `tests/ceremony.test.ts` with real headlines): a headline that only reports that something took place (уулзлаа / хүлээн авч / оролцлоо / бараалхлаа, a "шуурхай хурал боллоо", an MP's "ажлын тайлан", "… зохион байгууллаа", an opening, a visit) and names no decision (law, тогтоол, budget, tariff, ₮, appointment, court, hearing, protest, outbreak: `DECISION`) keeps importance ≤ `CEREMONY_MAX` (40) whatever the model said (`capImportance` in `analyzeArticle`; `ai:process` re-caps last 45 days' stored rows each run). In Oct 2026 the models scored 59 such headlines 45–90 and one led a digest. `rankScore` takes 30 more off them and `leadWithNews` moves them behind real news in every edition. `/method#importance` says so.
- Tier 1 also returns `importance_score` (0-100, national significance; optional, null when missing) and `topic` (one of `AI_TOPIC_KEYS`, unknown → null). `npm run ai:topics` tags older articles 25 headlines per call (runs after ai:process in the pipeline, a no-op when all are tagged); fallback rows are skipped and a row the model answered for twice without a usable topic (`scrape_meta.topic_attempts`, `TOPIC_MAX_ATTEMPTS`) keeps its domain topic.
- The article page names the model that really wrote each block (latest successful `tier1` / `tier2` call in `ai_usage_logs`, admin re-analysis logged as `admin_tier1` / `admin_tier2`, `aiModelLabel()`); never hardcode a provider name in reader-facing copy.
- `digest.ts`: "Онцлох тойм". `finalItems` enforces `MIN_DIGEST_STORIES` on the editor model's *final* list (invented ids dropped): fewer → the rule-based ranking writes the edition. Stories are excluded from the next editions by article id and by cluster (`clustersOf`). Articles are pre-ranked without AI (`rankScore`: importance, risk, cross-source coverage, source weight), one per cluster, top 40 (70 for "30d") go to the editor model (tier2 chain minus Grok), which picks 10 (20) and writes headlines + "why it matters". Model-invented ids are dropped, and the editor's items are validated one by one (`DigestSchema`: a bad id or empty headline drops that item, a null "why" is empty, never "null"); with no AI it falls back to the rule-based ranking. "12h" editions skip if one exists < 6 h old and do not repeat stories from the last 3 editions. A 12h edition needs `MIN_DIGEST_STORIES` (5): with fewer it widens to 24 h, then skips (no 1-story edition, no push). Scheduled editions come from the pipeline step `npm run digest -- --due` (`isDigestDue`: Ulaanbaatar 06–11 or 17–23 and ≥ 8 h after the last one), because GitHub starts `news-digest.yml` ~4.5 h late. The home strip labels an edition by its real time ("ОРОЙН ТОЙМ · 21:40"). The rule-based title names the top story. `DIGEST_WINDOWS` lives in the client-safe `src/lib/edition.ts`; page copy quotes it through `digestWindowsLabel()` ("өглөө 06–11, орой 17–23 цагийн хооронд"; never a fixed "08:00"). A rule-based edition says so wherever it is sent (`ruleBasedNote`: Facebook/Telegram, Instagram, Discord, the short form on Threads, the push body), not only on /digest.
