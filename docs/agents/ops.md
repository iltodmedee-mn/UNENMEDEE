# Admin, automation and repository security

Rules for this area, moved from `CLAUDE.md` with its section numbers. Keep each rule here, in one place; the reason behind a change goes to `docs/HISTORY.md`.

## 8. Admin & automation
- Public queries (`src/lib/queries.ts`) time out after `QUERY_TIMEOUT_MS` (10 s). `safe()` returns the empty fallback only with no `DATABASE_URL` or during `next build` (`NEXT_PHASE`): a hung `'use cache'` function would otherwise fail the build. At runtime it rethrows, because a rejected `'use cache'` call is not cached: a database blip costs one request, never an hour of a cached empty page or a 404 for an existing article.
- Headers (`next.config.ts`): explicit HSTS `max-age=63072000; includeSubDomains` (no preload), nosniff, `X-Frame-Options: DENY`, referrer and permissions policies, the CSP above. `xmlEscape` drops XML-forbidden control characters (one scraped title broke feed.xml). `sitemap.xml` reads only slug + date (`getSitemapSlugs`). Every table has row-level security (`social_posts` since migration 0014): add `ENABLE ROW LEVEL SECURITY` to every new table's migration.
- Contact: `info@iltodmedee.mn` (`CONTACT_EMAIL` in `site.ts`; Porkbun email forwarding to the owner's inbox, MX `fwd1/fwd2.porkbun.com`, receive only). Shown in the footer, `/support`, `/about`, `/privacy` through `EmailLink` (`src/components/iltod/email-link.tsx`: with a mouse Gmail's compose page `mail.google.com/mail/?view=cm&to=…` in a new tab, on a touch screen `mailto:`, which opens the phone's mail app; the `pointer-*` media variants pick one, no client JS), the Organization JSON-LD (`email`, `contactPoint`), `/.well-known/security.txt` (a route, `src/app/.well-known/security.txt/route.ts`: `Expires` = one year from the cached copy, refreshed daily, so it never lapses), README, CONTRIBUTING and SECURITY.md.
- Production domain: `https://iltodmedee.mn` (Porkbun DNS: apex A records + `www` CNAME to Vercel; Let's Encrypt cert auto-renews). `www` and `unenmedee.vercel.app` 308-redirect to it; `NEXT_PUBLIC_SITE_URL` is set on Vercel. Do not proxy it through Cloudflare (orange cloud): Vercel is already the CDN, and a second proxy breaks cert renewal and caching.
- Vercel functions run in `sin1` (Singapore, `vercel.json`), next to the Supabase database in ap-southeast-1; keep them in the same region.
- A main commit that changes only `docs/`, `tests/`, `scripts/`, `.github/`, `.claude/` or Markdown is not deployed (`vercel.json` `ignoreCommand`: `git diff --quiet HEAD^ HEAD` on the rest; exit 0 skips). Every deploy re-renders each crawled page (the cache key includes the deployment) and each render reads Supabase: six deploys on Nov 9 2026 put the article pages first among the egress readers. Batch site changes into fewer PRs. If `HEAD^` is missing the diff fails and the build runs.
- Vercel Hobby storage (10 GB "Functions Storage", Oct 2026 at 8.8 GB): `next.config.ts` `outputFileTracingExcludes` keeps `sharp` and `@img/*` (libvips glibc + musl + wasm, ~35 MB) out of every function, since Vercel optimizes `next/image` itself and `next/og` uses Satori: the largest function went from 68 MB to 19.5 MB. `vercel.json` `ignoreCommand` builds only `main`: branch pushes made a preview deployment each (CI's `check` job already builds every PR). A skipped build still counts toward Hobby's daily deployment limit (Oct 2026: a day of branch pushes hit "Deployment rate limited — retry in 24 hours" and two merges never went live), so `git.deploymentEnabled` turns Git deployments off for `claude/**` and `dependabot/**` branches entirely. Old deployments keep their old bundles until removed (Oct 2026: Functions Storage 9.96 / 10 GB after a day of merges), so `vercel-cleanup.yml` (daily, `npm run vercel:cleanup`, `src/lib/vercel-cleanup.ts`) deletes every deployment except the one serving production, the newest 3 ready production ones and unfinished builds; it needs the `VERCEL_TOKEN` secret (project/team ids default to this project), and deletes nothing in a run where the deployment serving production is unknown or missing from the list. Keep a Deployment Retention policy set in the Vercel project settings too.
- `/admin` is protected by `src/proxy.ts` (optimistic redirect) AND `requireAdmin()` at the top of every admin page and server action (`src/app/admin/actions.ts`). Server actions are callable directly, so never skip the second check.
- Login/logout live in `src/app/admin/auth-actions.ts`, apart from the heavy actions: jsdom failed to load on Vercel (ERR_REQUIRE_ESM) and took the whole actions module, login included, down with it. jsdom is only imported lazily through `extractArticleSafe` (cheerio fallback).
- `ADMIN_SECRET_PASSWORD` must be 12+ characters; the cookie is `<issuedAt>.<HMAC>` and expires after 7 days (`SESSION_MAX_AGE_S`); logout signs every session out on the server too (`app_settings` key `admin_session_floor`, `src/lib/admin-session.ts`: `requireAdmin()` refuses tokens issued at or before it; the proxy stays optimistic and never loads pg); rotating the password logs everyone out.
- URLs typed by a person (admin "analyze this URL") go through `fetchPublicUrl` (`src/lib/scraper/public-url.ts`): http(s) on 80/443 only, every redirect hop re-checked, private/loopback/link-local/metadata IPs refused (SSRF). IPv6 is parsed to bytes (`ipv6Bytes`) and every spelling that embeds an IPv4 host (mapped `::ffff:7f00:1`, compatible `::7f00:1`, NAT64 `64:ff9b::`, 6to4 `2002:`) is checked as that IPv4 address (`embeddedIpv4`).
- Error pages: `src/app/error.tsx` (Mongolian, "Дахин оролдох" = `retry()`) and `global-error.tsx` (own `<html>`, inline styles); the header's `LiveStatus` and `DonateChip` swallow a query error (fallbacks) so a DB blip in decorative parts never reaches the root layout. Numeric route ids go through `parseRouteId` (`site.ts`, `^\d{1,9}$`): `/clusters/abc` and `/officials/3000000000` never reach Postgres (404 once cached, see §2), not a 500.
- Generated images (`/ig-image`, `/story-image`) 308 to their canonical query (`canonicalImageQuery`: only `d`/`a` or `p`, once each), so a junk parameter cannot bypass the CDN and force a fresh render each request; an unknown slug's OG image is `notFound()`. Keep our own image links canonical (slugs are `[a-z0-9-]`; `encodeURIComponent` matches URLSearchParams for them).
- `subscribePush` is public: 60 per IP per hour (per instance; Mongolian carriers put many readers behind one IP), `PUSH_NEW_PER_HOUR` (500) new rows per hour and `PUSH_MAX_SUBSCRIPTIONS` (50k) in total, so nobody can fill the free database.
- `transparency_ledger` income (`ad_revenue_usd`, `donations_usd`) is nullable (migration 0017): a month nobody entered reads "бүртгээгүй", never "$0.00"; an empty admin field stores null. `/data` drops blacklist entries whose ban has ended whenever the hourly cache refreshes (`activeBlacklist` in `getOpenDatasets`), not only on sync day. `/method` quotes `RISK_FLAG_THRESHOLD`. `tests/topics-seeds.test.ts`: every topic domain is a seeded source and every national source has a topic (the court's `constcourt.mn` → `conscourt.gov.mn`).
- Withdrawn stories stay withdrawn: `getDigests` drops an edition's line once its article is unpublished (Nov 2026: the 72 empty gov.mn posts unpublished after #195 stayed in /digest and linked to 404 pages) and attaches the current summary and link only while it is published, and a cluster with no published member is gone (`getCluster` → 404, left out of `getClusters`); with a single source left its cross-source synthesis is not shown. Drizzle Studio (`db:studio`) was removed: its local bridge accepted SQL from any browser origin. Use the Supabase dashboard.
- Editing article text sets `edited_at` and the public page says so; `content_hash` keeps proving the original scrape.
- `.github/workflows/autonomous-news-pipeline.yml` (four crons: `17 */2`, `47 1-23/2`, `32 */2`, `2 1-23/2`, i.e. an attempt every 30 min off the congested minute 0; GitHub drops scheduled runs of public repos under load: a single 2-hourly cron ran only 3 times on Oct 26 2026, 4-7 h apart, and on Oct 29 three hourly attempts in a row were dropped (01:16 → 05:50), so the site shows no news for hours; the concurrency group keeps attempts from overlapping and queues at most one; on Oct 29 none of the four crons started for two hours, so the database is the fallback: the run's second step `npm run pipeline:mark` writes `app_settings.pipeline_started_at`, and the pg_cron job in `supabase/pipeline-fallback.sql` (applied by hand in the SQL editor, `private.dispatch_pipeline_if_idle()` every 10 min) POSTs GitHub's `workflow_dispatch` when no run started for 60 min and none was dispatched for 30 min, with a fine-grained token (this repo, Actions read/write only) in Supabase Vault `github_dispatch_token`; no token = no-op; setup, checks and rotation in `docs/PIPELINE-FALLBACK.md`): migrate → scrape (HTTP + Chromium) → AI → push → due digest + its push. Every step after the migration runs `if: !cancelled() && steps.migrate.outcome == 'success'`: a scrape or AI failure never skips the digest, its rule-based fallback or the pushes. The Playwright cache and the Chromium install are `continue-on-error` (`id: chromium`); when the install failed the scrape still runs with `--no-browser` (one apt hiccup used to skip all scraping). `npm ci` retries once after 60 s in the pipeline and news-digest. In `news-digest.yml` the digest, push, social, quiz and weekly steps carry the same `!cancelled() && migrate` guard. `FB_GRAPH_VERSION` / `IG_GRAPH_VERSION` repository variables reach every posting step (and `messenger.ts` reads `FB_GRAPH_VERSION` on Vercel): bump them when Meta retires v26.0 (~2028). `news-digest.yml` (08:07 / 20:07 Ulaanbaatar): opendata.mn sync + 12h digest; manual run with `kind=30d` for a monthly review. `discover-sources.yml` (weekly). The pipeline's manual run takes `days` for a backfill. `ci.yml`: check + build without secrets, also weekly on main (Tuesday 04:23 UTC) so a clock-dependent break shows up without a push. Tests whose fixtures are dated (2026 pages, the Gemini voice price that changes on 2027-01-01) call `pinClock()` (`tests/helpers/fixed-clock.ts`); never compare code that reads the real clock with a fixed date or "this year" (audit Nov 2026: 7 failures on 2027-01-05 would have blocked every merge, Dependabot security fixes included). Workflow inputs reach shell scripts only through `env:`. Secrets never reach `npm ci` / `playwright install` (dependency install scripts): job-level secrets are blanked on those steps, or set only on the steps that use them; keep it that way for new workflows and secrets.

## 8b. Autopilot (runs for months with nobody touching it)
- Home feed check (`src/lib/feed-check.ts`, `npm run feed:check`, pipeline step `feed_check` after the press sync, every 30 min): the newest 40 home-feed stories against outcome rules (Cyrillic, no "undefined"/empty text, no duplicate headline, at most `FLOOD_MAX` 4 undated stories of the top `FLOOD_TOP` 20 from one site (dated ones never count: gov.mn and parliament.mn post for many bodies), no undated story that names only past years, no future date). Read-only; the job `feed_issue` (the only one with `issues: write`) opens, updates (only when the problem set in the marker line changes) or closes the `feed-check` issue. Scraped titles in the issue go through `oneLine` with `@` and backticks replaced.
- `keepalive.yml` (daily): lists every workflow through the API, re-enables each one (`disabled_manually` is left alone with a warning) and fails red when one is still not active; GitHub otherwise disables schedules after 60 days without repository activity. Daily, not monthly: GitHub drops scheduled runs of public repos, and one dropped monthly run meant 61+ days and every schedule, keepalive included, disabled for good. No list to maintain.
- `npm run db:prune` (`--dry-run`; daily in news-digest, `RETENTION_DAYS` repository variable; rules in `src/lib/retention.ts`, tests in `tests/retention.test.ts`): the database grew 1.25 MB/day in Oct 2026 and nothing was ever deleted, and at 500 MB Supabase goes read-only and the pipeline stops. Every step runs in batches of 500 rows. Bodies older than `RETENTION_DAYS` (180) are cut to a 600-character excerpt (`content_pruned_at`; never an admin-edited body); title, AI summary, facts, link and the original SHA-256 stay, and the article page says so. Unpublished rows older than 90 days (not clustered, not edited) are deleted after their URL and hash go into `seen_urls` (migration 0016), which `db-sink` (`filterNewUrls`, the hash check) consults, so they are never fetched again; `seen_urls` forgets rows after 400 days. `retentionPlan(dbMb)` tightens itself: ≥ 350 MB bodies after ≤ 90 days and unpublished after 30; ≥ 420 MB bodies after ≤ 45 days and (the owner's choice) published stories over 2 years old with no cluster, importance < 40, not legalinfo.mn, not edited and not in any digest are deleted too. AI call logs older than 13 months (`LOG_KEEP_MONTHS`) go, except the successful tier1/tier2 call of an existing article (the page names its model); `/transparency` labels the provider table "сүүлийн 13 сар" and takes the all-time cost from `transparency_ledger`; `syncLedgerAiCost` never recomputes a month older than 12 (`monthRecomputable`). Each run writes `app_settings.prune_state` (counts, sizes, running `articlesDeletedTotal` / `analyzedDeletedTotal`, which `getSiteStats` adds back to the public counters; `deletedTotals`). It also stores headlines still in capitals in sentence case (`unshoutTitle`; slugs stay).
- Backups (`backup.yml`, weekly Thu 04:11 Ulaanbaatar + dispatch; `src/lib/backup.ts`, `tests/backup.test.ts`, `docs/BACKUP.md`): there was no backup, and the VAPID pair (= every push subscriber), the live Threads/Instagram tokens and the archive lived in one free project. `exportTables` writes `{"t","r"}` NDJSON in foreign-key order, 500 rows a page by primary key, through `getDb()` (the runner's pg_dump 16 refuses Supabase's PG 17); `ai_usage_logs` and `open_datasets` are left out. The job streams `db:backup | gzip -9 | age -r $BACKUP_AGE_PUBLIC_KEY` (plain text never on disk), checks the `age-encryption.org/v1` header, uploads only the `.age` file (`actions/upload-artifact`, 90 days; public-repo artifacts are downloadable by any signed-in user) and then writes `app_settings.backup_last_at` (`--mark`). No key or a non-`age1` value → red step with the fix. `importLines` upserts by primary key (`--table`, `--dry-run`, `--yes` required to write) and moves serial sequences, all in one transaction (a failed line leaves the database as it was). The watchdog says so while `BACKUP_AGE_PUBLIC_KEY` is missing (`BACKUP_CONFIGURED` boolean) and when the last backup is > 10 days old. The owner keeps the age private key offline; never ask for it or print it.
- Stale data is visible (Oct 2026): `DataAge` (`src/components/iltod/data-age.tsx`, `staleAfter` in `src/lib/stale.ts`, clock in a `'use cache'` hourly entry so pages stay static) prints "Шинэчилсэн: …" and "хуучирсан өгөгдөл" past the limit under the macro strip (3 d), /budget Шилэн данс (14 d) and audit.mn (30 d), and every /data panel (`synced_at`, 3 d; the source's own date is labelled "эх сурвалж шинэчилсэн"). `editionLabel(d, now)` adds "· 25.10" to an edition older than `EDITION_DATE_AFTER_H` (18) on the home strip (`stripLabel`, hourly cache); posts and OG cards call it without a clock. After `FEED_QUIET_HOURS` (6) without a feed story the header's `LiveStatus` shows a grey dot and "Сүүлийн мэдээ N цагийн өмнө" (`quietHours`, hours cache) and the ticker drops "Дараагийн шалгалт". `ArticleListItem.summaryFallback`: StoryList titles such a block "Эх текстийн эхний өгүүлбэр · AI ажиллаагүй" and shows no SpinMeter. `/sources`: `staleDays` (computed in the cached SQL) > 7 → grey "Удаан шалгаагүй". README has the owner checklist (MN + EN).
- AI fallback (`src/lib/ai/fallback.ts`, start of `ai:process`): articles still unsummarized after 24 h, or parked with `ai_error`, get their first sentences as the summary (`summary_fallback`, importance 30, page label "AI ажиллаагүй", no fact/spin panel), so news keeps appearing if every provider fails.
- Debuggability (Audit #4, Nov 2026: a failure's cause could not be captured): `errorLine(err)` (one line, the whole `cause` chain with codes, for issue lines and `last_error`) and `errorDetail(err)` (chain + response body + first stack frames, continuation lines indented so nothing after `::error::` starts a second workflow command) in `src/lib/log-safe.ts`; every script's `main().catch` prints `::error::` + `errorDetail`. `ai:process` treats an error that is not `AIUnavailableError` as a code bug (`::error::` with the stack, exit code 1, the article stays queued) instead of a 160-character "provider hiccup". The router reads `finish_reason`/`finishReason`: a reply cut at the output limit is `TruncatedError` (repaired once with twice the tokens, parked like bad JSON, never a trip), and every non-transport failure (429, request-specific 400, bad reply with its first/last 120 characters) is one `[ai]` warning; the OpenAI SDK's "Connection error." carries its `cause`. `readJsonBody(res)` (`src/lib/read-json.ts`) replaces `res.json().catch(() => ({}))` for Gemini, TTS, ElevenLabs and every social wrapper: a failed non-JSON answer (an HTML 502) names the status and the text; a successful one without JSON stays `{}` (outcome unknown, never a refusal). The pipeline and news-digest end with "Fail the run when a step failed" (`toJSON(steps)`, every step has an `id`; the Chromium install is left out): the `continue-on-error` steps still all run, but a failed one makes the run red so the watchdog's workflow check sees it. The watchdog uploads `health.txt` / `layout.json` / `tax-rates.md` as an artifact when the check failed; keepalive no longer reads a failed listing as "nothing stuck". Error pages (`error.tsx`, `global-error.tsx`, `admin/error.tsx`) show Next's `digest` as "Лавлах код" with a "Мэдэгдэх" mailto (`src/lib/error-report.ts`); `src/instrumentation.ts` `onRequestError` logs the same digest with path and `errorDetail`, and (Node runtime with a database, never at build) counts it in `site_errors` (`src/lib/site-errors.ts`: one row per route pattern + first message line, no query string, headers or body; rows unseen for 30 days are deleted on the next write; a failed write is swallowed). Readers' phones too (Nov 8 2026, the owner refused Sentry: its 30–60 KB client would slow the phones 90 % of readers use): an inline handler in the root layout (`src/lib/client-error-script.ts`, < 700 bytes, `tests/client-errors.test.ts` keeps it so) sends the page view's first own-origin JavaScript error with `sendBeacon` to `/api/client-error`, at most once per browser per day (localStorage) and from 1 browser in 10 (`CLIENT_SAMPLE`; the watchdog shows client counts × 10 as «≈N уншигч»), so a page broken for everyone stays a trickle; which stores it as `CLIENT /<first segment>[/*]` (`src/lib/client-errors.ts`: message ≤ 200, "Script error." and other origins dropped, 10 reports per IP per hour, one database write per error per instance per minute with the counts in between added on the next write, at most 200 client rows, always 204). Never add an error-tracking library to the client. The watchdog names the 5 most frequent routes of the last 24 h (🟡); `@` and backticks in a message are neutralised before they reach the issue.
- Versions and a clean reproduction (Audit #4 PR 2): Node 24 is pinned by `package.json` engines, `.nvmrc` and `.node-version` (no `engine-strict`: Dependabot's updater runs its own Node and would fail; `demo.mjs` refuses an older Node with the fix named); `npm ci`, never `npm install`, in the docs. Every `scripts/*.ts` entry imports `@/lib/runtime-banner`, which prints `runtimeLine()` (`src/lib/runtime-info.ts`: script, Node, platform, commit, database kind by host only, Actions/Vercel, args) as its first line (silent in tests and with `RUNTIME_BANNER=0`); CI prints `node -v && npm -v`, the video steps `ffmpeg -version` and Playwright's version. `npm run doctor` (`scripts/doctor.ts`) checks Node, the lockfile, `node_modules` against it, Chromium, ffmpeg and `.env` names unknown to `.env.example`; `--clean` removes `.demo-db/` and `.next/` and seeds the demo again (the one "fresh start"). ## 8c. Repository security

## 9. MCP
`.mcp.json` is git-ignored (it named the Supabase project). To use the Supabase MCP server locally, create it with `claude mcp add --scope project --transport http supabase "https://mcp.supabase.com/mcp?project_ref=<your-project-ref>"`, then `claude /mcp` → supabase → Authenticate.
- The repository is linked from the site again (footer, `/method`, `/transparency`, JSON-LD `sameAs`) via `REPO_URL` / `repoFile()` in `src/lib/site.ts`, now that the repo is hardened (§8c). The scraper's User-Agent and the VAPID subject still point to https://iltodmedee.mn.
- `/method` renders the live prompts (`TIER1_SYSTEM`, `TIER2_SYSTEM`, `DIGEST_SYSTEM`) verbatim and says the risk score is an AI estimate; the article page links to `/method#risk` next to the risk badge. Keep it in sync when prompts or thresholds change (it imports them, so text updates itself).
- A stuck deployment is caught every pipeline run: `/api/pulse` returns the commit the live build came from (`VERCEL_GIT_COMMIT_SHA`), and the feed check (`deployProblem` in `src/lib/feed-check.ts`) compares it with the run's `GITHUB_SHA`; a `main` commit older than 60 minutes that is not live opens the `feed-check` issue with what to check in Vercel (Nov 6–8 2026: after the move to the organization Vercel received no pushes, and ~40 merged fixes never reached readers).
- Snapshot purge retry (Nov 10 2026): `scripts/write-snapshots.ts` stores each list page's new hash before it asks the site to purge. When that purge fails (an error answer, a timeout), `forgetHashes` (snapshot-writer.ts) blanks the stored hash of the changed pages so the next run reports them changed and purges again; before, the next run saw "nothing changed" and the page, cached for a day and refreshed only by a purge, kept its old list (a withdrawn story included).
- Egress check (Nov 2026, Supabase free egress 5 GB/month): measure, do not guess. Snapshot (read-only, through the Supabase MCP `execute_sql` or psql): `select now(), string_agg(queryid||':'||calls||':'||rows, ' ') from (select queryid, calls, rows from pg_stat_statements s join pg_roles r on r.oid = s.userid where r.rolname = 'postgres' order by greatest(rows, calls*5) desc limit 220) t`; save the line, take another later, then `node scripts/egress-diff.mjs before.txt after.txt` lists the queries that read the most in between; look one up with `select query from pg_stat_statements where queryid = …`. Rows × the columns' real size (`octet_length`) gives bytes. Facts measured on Nov 10 2026: with no deploy the site read ~185K rows a day; a deploy empties every `use cache` entry (in-memory, keyed by build) and the next renders read again, so the egress chart follows deploys per day (Oct 23, no deploy: ~90 MB; Nov 9, 11 deploys: 672 MB).
- Deploys cost egress: a PR that changes the site (`src/`, config) is a deploy (docs, tests, scripts and workflows skip it, vercel.json `ignoreCommand`). Batch site changes into one or two merges a day; merge a docs-only or script-only PR any time.
